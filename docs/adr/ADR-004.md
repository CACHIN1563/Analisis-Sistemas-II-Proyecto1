# ADR-004: Representación de importes monetarios

| **Campo** | **Contenido** |
|-----------|---------------|
| **Título** | ADR-004: Representación de importes monetarios como Objeto de Valor inmutable |
| **Estado** | Aceptada |
| **Fecha** | 25/08/2026 |
| **Contexto** | El sistema maneja dinero en un dominio financiero (microcréditos). Los cálculos incluyen amortizaciones, intereses, moratorios, saldos y cartera en riesgo. Un error de redondeo o precisión puede generar descuadres contables, afectar la confianza de la gerencia y violar regulaciones. JavaScript/TypeScript usa Number con punto flotante binario (IEEE 754), que no puede representar con exactitud centavos de quetzal (ej: 0.1 + 0.2 ≠ 0.3). Además, sumar quetzales con dólares no tiene sentido y debe ser impedido por diseño. |
| **Decisión** | Se implementa un Objeto de Valor Dinero inmutable, que encapsula: <br/>- monto como entero en centavos (o usando decimal.js)<br/>- moneda (Q, USD, etc.)<br/>- Redondeo a 2 decimales, medio hacia arriba, aplicado en cada cuota<br/>- Métodos sumar(), 
estar(), multiplicar(), comparar() que devuelven un nuevo Dinero<br/>- Prohibición de sumar monedas distintas (error en tiempo de compilación o runtime validado con Zod)<br/><br/>**Alternativas consideradas:** <br/>1. Usar Number con enteros en centavos (sin tipo). Se descarta porque permite sumar inadvertidamente valores sin moneda y no hay garantía de inmutabilidad.<br/>2. Usar ig.js o decimal.js directamente sin encapsular. Se descarta porque no fuerza el tipo de moneda ni el redondeo consistente.<br/><br/>**Justificación:** <br/>- Cumple la regla no negociable de la sección 6.2.<br/>- Permite pruebas unitarias deterministas.<br/>- Facilita la auditoría: cada Dinero es trazable. |
| **Consecuencias** | **Positivas:** <br/>- Cero errores de precisión por punto flotante.<br/>- El compilador TypeScript impide operaciones inválidas (monedas distintas).<br/>- Inmutabilidad natural para cálculos financieros (sección 6.10).<br/><br/>**Negativas:** <br/>- Curva de aprendizaje inicial para el equipo.<br/>- Requiere convertir siempre desde y hacia centavos en las capas de entrada/salida (adaptadores).<br/><br/>**Compromiso asumido:** El costo de implementar y mantener Dinero se considera menor que el riesgo de descuadres contables. Se acepta la sobrecarga de crear nuevos objetos en cada operación aritmética. |
