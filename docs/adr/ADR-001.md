# ADR-001: Selección de Arquitectura Hexagonal

**Estado**: Aceptada
**Fecha**: 25/08/2026

## Contexto
El Sistema de Gestión de Microcrédito debe garantizar exactitud matemática a nivel de centavos, al mismo tiempo que debe soportar la incorporación futura de nuevas interfaces como un frontend en React y un servidor MCP para Inteligencia Artificial. Mezclar las reglas del negocio con el código de la API dificultaría las pruebas automatizadas y el mantenimiento.

## Decisión
Se decidió adoptar el estilo arquitectónico de **Arquitectura Hexagonal (Puertos y Adaptadores)**. Toda la lógica financiera y de dominio se implementa en un núcleo puro de TypeScript, sin dependencias de bases de datos, redes o frameworks web (Express). 

## Consecuencias
* **Positivo:** Permite ejecutar miles de pruebas unitarias sobre el motor matemático en milisegundos sin levantar infraestructura.
* **Positivo:** Garantiza que el asistente de IA y la API web consuman exactamente los mismos casos de uso, evitando duplicidad de reglas.
* **Negativo/Compromiso:** Introduce una curva de aprendizaje inicial para el equipo al tener que mapear entidades de dominio hacia esquemas de la API (Zod) a través de los adaptadores, aumentando ligeramente la cantidad de código inicial (boilerplate).
