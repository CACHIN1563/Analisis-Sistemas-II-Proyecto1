# ADR-002: Representación del Dinero como Enteros (Patrón Value Object)

**Estado**: Aceptada
**Fecha**: 25/08/2026

## Contexto
En un entorno financiero, usar el tipo de dato nativo \Number\ (punto flotante) de JavaScript o bases de datos produce errores de precisión por redondeo (ej. 0.1 + 0.2 = 0.30000000000000004). Una diferencia de un centavo acumulada en miles de créditos genera serios problemas contables y legales.

## Decisión
Se prohíbe estrictamente el uso de punto flotante para importes monetarios. Se implementó el patrón **Value Object** creando la clase inmutable \Dinero\. Todo importe se maneja internamente como un número entero representando centavos (ej. Q100.50 se almacena como 10050) utilizando la librería nativa o lógica estricta para evitar decimales corruptos.

## Consecuencias
* **Positivo:** Elimina por completo los errores de precisión por coma flotante, cumpliendo con la auditoría de la Superintendencia de Bancos.
* **Positivo:** La inmutabilidad garantiza que al sumar o restar saldos no se sobreescriba por error el saldo original.
* **Negativo/Compromiso:** Exige que los adaptadores de la API (y en el futuro la base de datos) conviertan los enteros a un formato legible para el humano (ej. dividir entre 100) al momento de responder JSONs o mostrar en pantalla, añadiendo un paso extra de serialización.
